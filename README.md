# Рабочий почерк — тест-лендинг

Одностраничный тест о рабочих привычках: 21 вопрос, 7 шкал, результат с процентами
и ссылкой, которой можно поделиться.

Всё лежит в одном файле — `index.html`. Ни сборщиков, ни npm, ни внешних библиотек.
Файл открывается двойным кликом и работает офлайн.

```
index.html    вся страница: разметка, стили, логика и весь текст
preview.png   картинка 1200×630 для превью ссылки в мессенджерах
README.md     этот файл
```

---

## Как это устроено

Пять экранов, которые переключаются без перезагрузки страницы:

| Экран | Что показывает |
|---|---|
| Интро | Заголовок, «21 вопрос · 5 минут», кнопка «Начать тест», список из 7 шкал |
| Квиз | По одному вопросу, линейка прогресса с 21 засечкой, 4 варианта, кнопка «Назад» |
| Загрузка | Пауза 3,5 секунды с прогрессом и сменой подписей |
| Результаты | 7 шкал горизонтальными барами, по убыванию, с текстом под каждую |
| Финал | Блок «Что дальше», CTA-кнопка и «Пройти заново» |

Полезные детали:

- **Прогресс сохраняется.** Закрыли вкладку — вернётесь на тот же вопрос.
  Хранится в `localStorage` браузера, никуда не отправляется.
- **Результатом можно поделиться.** После подсчёта в адресе появляется `#r=1-5zwgafe4`.
  Кто откроет такую ссылку, сразу увидит экран результатов.
- **Клавиатура.** Ответ — клавиши `1`–`4`, назад — стрелка влево.
- **Тёмная тема** включается сама, если она включена в системе.
- **Никаких сборов данных:** ни почты, ни телефона, ни счётчиков, ни пикселей.

## Как поменять содержание

Весь текст лежит в объекте `CONFIG` в начале `index.html` (ищите строку
`const CONFIG = {`). Ниже — что где менять. **Код трогать не нужно.**

### Тексты экранов

Каждому экрану соответствует свой блок: `intro`, `quiz`, `loading`, `results`, `final`.
Меняйте значения в кавычках:

```js
intro: {
  eyebrow: 'Тест о привычках в работе',
  title: 'Как вы работаете на самом деле',
  lede: 'Двадцать один вопрос о том, как вы…',
  facts: '21 вопрос · 5 минут',
  start: 'Начать тест',
  …
}
```

Фигурные скобки `{n}` и `{total}` — это подстановки (номер вопроса и общее их количество).
Их можно двигать внутри строки, но не переименовывайте.

### Вопросы

Массив `questions`. Один вопрос выглядит так:

```js
{ scale:'delay', text:'Задача важная, но неприятная. Обычно вы…', options:[
  { t:'Берётесь за неё первой, пока день не разогнался', w:0 },
  { t:'Ставите на конкретное время и держите его',       w:1 },
  { t:'Переносите пару раз, потом делаете',              w:2 },
  { t:'Тянете до срока и делаете в последний момент',    w:3 }
]},
```

- `scale` — к какой шкале относится вопрос. Должен совпадать с `id` из массива `scales`.
- `text` — сам вопрос.
- `t` — текст варианта, `w` — сколько баллов он даёт: `0`, `1`, `2` или `3`.

Порядок вариантов может быть любым: не обязательно вести баллы от 0 к 3.
В этом тесте они местами идут по возрастанию, местами наоборот — так честнее,
человек не отвечает «по диагонали».

### Шкалы и тексты результата

Массив `scales`. Одна шкала:

```js
{
  id: 'delay',
  name: 'Откладывание',
  bands: [
    { from: 67, title: 'Высокое', text: 'Сложные задачи регулярно уезжают…' },
    { from: 34, title: 'Среднее', text: 'Вы откладываете выборочно…' },
    { from: 0,  title: 'Низкое',  text: 'Вы беретесь за неприятное рано…' }
  ]
}
```

`from` — нижняя граница диапазона в процентах. Показывается тот диапазон,
в который попал результат: 67 и выше → «Высокое», от 34 до 66 → «Среднее»,
ниже 34 → «Низкое». Границы можно двигать, диапазонов может быть больше трёх.

### Правило, которое нельзя нарушать

**Число вопросов должно делиться на число шкал нацело, и на каждую шкалу должно
приходиться одинаковое количество вопросов.** Сейчас это 21 вопрос ÷ 7 шкал = 3 вопроса
на шкалу, максимум 9 баллов, процент = сумма ÷ 9 × 100.

Если вы добавите шкалу — добавьте и 3 вопроса к ней. Если хотите 5 вопросов на шкалу —
сделайте по 5 у каждой. Иначе проценты у разных шкал перестанут быть сравнимыми.

### Цвета

Блок `theme` в начале `CONFIG`: отдельно `light` (светлая тема) и `dark` (тёмная).

```js
light: {
  paper:      '#EFE9DE',   // фон страницы
  surface:    '#F8F5F0',   // карточки, поля
  'surface-2':'#E7E0D2',   // дорожки шкал
  ink:        '#221F1A',   // основной текст
  muted:      '#57503F',   // вторичный текст
  line:       '#D6CDBC',   // декоративные линии
  'line-strong':'#8E8574', // рамки кликабельных элементов
  accent:     '#2E5A4F',   // кнопки и заполнение шкал
  'accent-ink':'#F8F5F0',  // текст на акценте
  'accent-dim':'#24473E'   // акцент при наведении
},
```

Если меняете цвета — проверьте контраст на [webaim.org/resources/contrastchecker](https://webaim.org/resources/contrastchecker/).
Нужно минимум **4.5:1** для пары «текст / фон» (`ink`/`paper`, `muted`/`paper`,
`accent-ink`/`accent`) и минимум **3:1** для `line-strong`/`paper`. Ниже этих значений
текст станет плохо читаемым на солнце и на плохих экранах.

> Та же палитра продублирована в CSS в самом верху файла (блок `:root`) — она нужна
> на случай, если JavaScript не выполнился. Если вы поменяли цвет в `CONFIG` и хотите,
> чтобы он совпадал и там, поправьте то же значение в `:root` и в блоке
> `@media (prefers-color-scheme: dark)`.

### Ссылка в CTA-кнопке

Сейчас там заглушка, и под кнопкой видна серая строка-напоминание. Впишите свой адрес:

```js
cta: {
  href: 'https://example.com/vasha-stranica',   // ← сюда
  label: 'Открыть подборку практик',
  …
}
```

Как только `href` перестанет быть `'#'`, напоминание под кнопкой исчезнет само.

### Длительность экрана загрузки

```js
loading: {
  durationMs: 3500,          // 3,5 секунды
  steps: [
    { at: 0.00, label: 'Считаю баллы…' },
    { at: 0.42, label: 'Собираю профиль…' },
    { at: 0.86, label: 'Готово' }
  ],
  …
}
```

`at` — доля от общего времени, на которой подпись сменится: `0.42` это 42 %.

## Деплой на GitHub Pages

Пошагово, с нуля. Понадобится только браузер.

**Шаг 1. Заведите репозиторий.**
На [github.com](https://github.com) нажмите `+` в правом верхнем углу → **New repository**.
Имя — любое латиницей, например `rabochiy-pocherk`. Поставьте **Public**
(на бесплатном тарифе Pages работает только для публичных репозиториев).
Нажмите **Create repository**.

**Шаг 2. Загрузите файлы.**
На странице пустого репозитория нажмите **uploading an existing file**.
Перетащите `index.html`, `preview.png` и `README.md`.
Внизу нажмите **Commit changes**.

**Шаг 3. Включите Pages.**
В репозитории откройте **Settings** (шестерёнка сверху) → в левом меню **Pages**.
В блоке *Build and deployment* → *Source* выберите **Deploy from a branch**.
Ниже в *Branch* выберите **main** и папку **/ (root)**. Нажмите **Save**.

**Шаг 4. Подождите 1–2 минуты.**
Обновите страницу Settings → Pages. Сверху появится зелёная плашка с адресом вида
`https://ВАШ-ЛОГИН.github.io/rabochiy-pocherk/`. Это и есть ваш сайт.

**Шаг 5. Проверьте.**
Откройте адрес, пройдите тест до конца. Скопируйте ссылку с результатом
и откройте её в другом браузере — должен сразу открыться экран результатов.

**Шаг 6. Адрес для превью ссылки.**
В `index.html` он уже прописан:

```html
<meta property="og:url"    content="https://viachkovdesign.github.io/quiz-landing/">
<meta property="og:image"  content="https://viachkovdesign.github.io/quiz-landing/preview.png">
<meta name="twitter:image" content="https://viachkovdesign.github.io/quiz-landing/preview.png">
```

Трогать это нужно только если вы переименуете репозиторий или переедете на свой домен —
тогда поправьте эти три строки. Адрес обязан быть полным: Telegram и другие мессенджеры
относительный путь не понимают и покажут ссылку без картинки.

**Шаг 7. Проверьте превью.**
Отправьте ссылку себе в Telegram и посмотрите, как она развернётся. Если картинки нет —
Telegram кеширует превью; отправьте ссылку боту `@WebpageBot`, он сбросит кеш. Если картинка не появилась — Telegram кеширует
превью; отправьте ссылку боту `@WebpageBot`, он сбросит кеш.

### Как обновлять потом

Поправили `index.html` на компьютере → в репозитории **Add file** → **Upload files** →
перетащили новый файл → **Commit changes**. Через минуту сайт обновится.

## Сетка и отступы

Если будете двигать вёрстку — вот числа, на которых она построена.

Ширина колонки контента — **720px**, и это не случайное число:

```
720 = 6 колонок × 100px + 5 гаттеров × 24px
```

Шесть колонок ровно по 100px — удобно делить на 2 и на 3, и любой блок
попадает в сетку без дробей.

| Устройство | Колонки | Гаттер | Поля по краям | Модуль |
|---|---|---|---|---|
| Мобильный (375px) | 4 | 16px | 20px | 4px |
| Планшет (768px) | 8 | 16px | 32px | 8px |
| Десктоп (от 784px) | 6 | 24px | 32px | 8px |

Шкала отступов — **4 / 8 / 12 / 16 / 24 / 32 / 48 / 64**. В CSS это переменные
`--s1 … --s16`. Промежуточных значений нет специально: чем меньше в макете разных
отступов, тем он собраннее.

Тач-цели — минимум 44px по высоте. Карточки ответов сейчас 56px и выше.

## Что стоит знать перед тем, как менять

- **Шрифты — системные.** Ни одного обращения в интернет, поэтому страница
  работает офлайн и открывается мгновенно. Google Fonts здесь намеренно не подключены:
  с ними файл перестал бы работать без сети. Заголовки — серифная связка
  (Iowan Old Style → Palatino → Georgia), интерфейс — системный гротеск,
  цифры — моноширинный шрифт.
- **Анимации отключаются сами**, если в системе включено «уменьшить движение»
  (`prefers-reduced-motion`). Не убирайте эти блоки из CSS и JS.
- **Прогресс-бары анимируются через `transform: scaleX()`**, а не через `width`.
  Это принципиально: `width` заставляет браузер пересчитывать раскладку каждый кадр
  и бар начинает дёргаться на слабых телефонах.
- **Не ставьте `transition: all`.** Перечисляйте свойства руками, иначе анимироваться
  начнёт то, что вы не планировали.
